## 快速开始

```bash
cd arm-control
python3 -m arm.executor --port 8770          # 真机，浏览器打开 http://127.0.0.1:8770/
python3 -m arm.executor --mock --port 8770   # 无硬件模拟
```

- 执行器只读 `config/executor.json` 里的 ECB IP、端口、绑定地址、目录；搬到 Linux 小主机只改这个文件。
- 网页只是执行器的一个客户端；关掉网页执行器仍在跑。网页不直接发 CAN/UDP。
- 端口、心跳、状态推送频率都在 `config/executor.json`。

## 配置和版本

| 文件 | 内容 |
|---|---|
| `config/executor.json` | 绑定地址/端口、ECB IP、目录、心跳/推送频率、默认执行模式 |
| `config/joints.json` | 六关节 ID/SN/型号/sign/offset/EEPROM 限位/软件限位/速度/加速度/限流/设零日期/`sign_checked`；`expected_count`=6（带夹爪 7）、`gripper_installed`；**J2 已按 P03 改为 EEPROM ±95°、软件 ±90°** |
| `config/tcp.json` | TCP 预设 `flange` 0、`probe` 90（临针，未实测）、`gripper_tip` 161.65、`gripper_center` 139.15（后两者 ψ=−19.2°，未装） |
| `config/park.json` | 18.1 搁架外形包络 + 18.3 三个停机点 / 接住比例 / 失能顺序 / `park_side` |
| `config/park_state.json` | 停机时写入的 `parked_q`、I₀/I₁（运行时生成，不属于 config_version） |
| `config/kt.json` | 18.4 Kt 标定结果（`kt_eff`/`offset`/`r2`/日期）；标定后自动热重载 |
| `urdf/gluon_2l6_4l3.urdf` | 运动学唯一数据源（m；程序内换 mm） |

`config_version` = joints.json + tcp.json + URDF 三个文件的 sha256 前 12 位。客户端拿控制权时比对，不一致拒绝一切运动命令。校准时 `zero_date`/`sign` 会改 joints.json，执行器会刷新版本，网页自动重新拿控制权。

## 16.3 网页校准（J6 → J5 → J4 → J3 → J2 → J1）

1. 打开网页 → 左栏 **校准（16.3）** → **打开校准向导**。
2. 选关节 → **开始**，确认臂已支撑。
   - 执行器先把其余关节全部失能；目标关节 **零扭矩使能**（电流模式，给 0 A），输出端可用手转。
   - 读电池电压（0xB7），<2.5 V 不做。
3. 面板实时显示角度/电机位置/电池/错误/模式/电流。按面板上的参考姿态说明，用手摆好。
4. **设为零位**：清 Homing → 当前位置设零 → 回读 |q|<0.05° → 写限位/限流/限速 → 存 EEPROM → 全部回读比对。任何不符：恢复原值、失能、报错。
5. **点动 +5°（电机正方向）**，看实际方向；按 16.1 关节表选 `sign=+1` 或 `−1`。选完自动回 raw 0 并失能。
6. 继续下一颗。六颗完成后，回“连接” → 连接真机 → 使能，进入 16.4 验收。

安全：校准期间每个关节的其余关节全部失能，臂必须支撑好；网页心跳断 0.5 s，执行器会自动结束校准并失能。

## 16.4 启动序列（零扭矩 + 成链）

`/api/enable`（网页“使能 J6→J1”）：

1. 握手 → 枚举 → 颗数（`expected_count`）和 ID↔SN 逐一核对，不符拒绝。
2. 用户确认臂有支撑。
3. J6→J1 一次一颗：先尽量设电流模式/0 A，再使能；使能后立刻再给 0 A，回读模式、电流、限流、速度限制、位置限位、母线电压，按 16.3 表核对。任何一项不过：这颗马上失能、整个启动停下、网页写明哪颗哪项。
4. 成链检查：比较母线电压；带 J7 时 B4AE 读数 +1.5 V；任何一颗比最高低 >1.0 V 报警并全部失能。
5. 全部通过：切 S 曲线模式（0x06），目标=当前位置，写 0x1F/0x20/0x21 并回读，就绪。
6. 启动流程不改写电机参数（限位/限流/限速只能走 16.3）。

注意：这颗固件失能时不回答位置/参数（只回 0xB7），所以“失能状态读位置”用零扭矩使能代替。B4AE 台架零扭矩试验还没做（J7 未接）。

## 直接执行 / 控制权 / 心跳

- `POST /api/acquire` 拿控制权（token）；同一时刻只认一个控制方，其他客户端只读。
- 状态推送 `GET /api/events?client_id=...`（SSE，20 Hz）；`/api/state` 可轮询。
- 网页每 200 ms 心跳；SSE 断开/心跳断 0.5 s，运动中按中止（原地保持），校准中自动结束并失能。
- 执行模式 `preview` / `direct`：验收 1–6 期间默认 preview；验收通过后默认改 direct。direct 下点完立即执行，自动检查一项不少；运动中再点桌面被忽略；空格 = 停。
- 中止 = 把每颗目标改成当前位置，保持使能；全部失能只在“已回零且扶住”或通信完全断时。

## 18 保护与停机（2026-11-09，P05–P07 / v8）

- **18.2 力矩模型**：`arm/gravity.py` 按 18.2 质点表算 J2–J5 的静态重力力矩（J1/J6 不检查），
  核对值表 8 行全部在 ±0.05 N·m 内（`python3 tools/gravity_selfcheck.py`，实测最大 0.005）。
  容量：J2 = min(支架, 回读限流×1.91)，支架 = `j2_bracket` 为 PLA 时 **8**、PETG100 时 12
  （P08-9；4 A 时仍是 7.64）；J3 = 6.5，J4/J5 = 2.3（Kt 标定后改 min(2.3, Kt_eff×限流)）。
- **预检**：每条路径的起点、终点、10 个插补点都查；任一点 |τ| > 0.8×容量 → 拒绝并写明关节/N·m。
  被拒绝时先试“远端先收”（先 q4–q6 到目标，再走 q1–q3），还不过再反序试一次
  （先 q1–q3，再 q4–q6），两次都不过才拒绝（P08-10）。点动、回零、停机同一套检查。
  保持中 τ/容量 >70% 连续 30 s → 网页提醒。`end_effector = gripper` 且 J2 回读 ≤4.5 A → 警告，
  容量仍按 7.64 算，所以带爪、前臂水平的姿态会被拒绝（故意）。
- **18.1 搁架**：v9/P08 起以 Mac 本地模型为正式版（`cad/park_rest_local.*`）：底座本体
  **100（沿管）×96**，4 个 16×16 脚耳在 ±x 侧（孔位沿管 ±35、横向 ±56；横向实际 122），
  顶部 80×44、高 127、V 槽尖 109/口宽 36；网页按 `config/park.json` 画占位（100×122），
  位置由 `park_side` 决定（−1 → (37.3, −290)）。围栏不把搁架当障碍。18.1a 腕托暂不建。
- **18.3 停机**：网页“停机”取代“全部失能”。前提三项勾选 + J2 限流与末端匹配；
  **只对 `end_effector = flange` 开放**（18.1a：带爪等腕托，先用扶持停机）。
  序列：抬高 → 收拢+折腕+转 J1（−90,30,30,90,0,0）→ 预停机点（−90,76.5,13.5,90,0,0，
  停 1 s 读 I₀）→ **1 mm/步分步下降找接触**（q2+q3=90，每步读 J2；J2 电流 ≤0.5·I₀ 算接住，
  再多走一步、读 I₁；最低到 J4 轴 z=130.5，仍没接住就回预停机点保持、不失能）
  → 写 `parked_q`（失能前最后一次读到的值）→ 按 J6→J5→J4→J3→J2→J1 每 0.5 s 失能一颗，
  每颗之后读**其余还使能的**关节，任一变化 >1° 就把刚失能的这颗重新使能到保持并停止。
  “扶持停机”仍保留（零位 + 扶住 + 二次确认）。启动后和 `parked_q` 差 >2° → **硬拦**：
  拒绝一切运动，网页点“已确认”才解除；“抬回预停机点”把 J2/J3 抬离搁架。
  中止保持状态只有三个出口：**恢复**（`/api/recover`，网页按钮）、停机、扶持停机；不先恢复，
  普通运动命令会被拒绝。
- **18.4 Kt**：网页“Kt 标定向导”。标定点（J2 4 点；J3/J4 共用 (0,0,90,0,0,0) 挂 0/0.25/0.5/1 kg；

  `τ = Kt_eff·I + b` 线性拟合，结果写 `config/kt.json`，J4/J5 容量改成 min(2.3, Kt_eff×回读限流)。
  **状态：代码完成，等硬件。**
